# K-Decision: 한국 특화 디시전 모델 개발기
## 14세대 실험으로 찾아낸 단일 GPU 0.818의 여정

---

### 1. 프로젝트 개요

**K-Decision**은 상태(state)와 타이핑드 질문(typed questions)을 입력받아, 모든 옵션에 **보정된 확률 분포**를 붙인 구조화 결정을 **단일 forward 패스**로 반환하는 의사결정 엔진입니다.

- **개발**: ONYULTEA
- **하드웨어**: RTX 3090 단일 (24GB) — 학습·서빙 모두
- **기간**: 2026.10.24 ~ 11.09 (약 2주)
- **결과**: 국제 벤치마크 LocalLLaMA/typed-decisions **2위 (0.818)**
- **모델**: Qwen3.5-9B + int8 LoRA (r=32), Apache-2.0 공개

---

### 2. "디시전 모델"이란?

2026년 하반기 허깅페이스에서 급부상한 신규 카테고리:

```
전통 LLM:  "질문을 읽고 → 텍스트를 생성 → 답변 추출"
디시전 모델: "질문을 읽고 → 정답 심볼 로짓만 예측 → 확률 반환"
```

| 특성 | 일반 LLM | 디시전 모델 |
|------|----------|-----------|
| 출력 | 자유 텍스트 | 구조화 확률 |
| 속도 | 수초 (디코딩 루프) | ~100ms (단일 패스) |
| 비용 | 높음 | 1/50~1/100 |
| 확률 신뢰도 | 낮음 (불보정) | 높음 (ECE 0.001) |
| 용도 | 범용 | 라우팅·분류·게이팅·판단 |

**시장 상황**: 허깅페이스에서 "decision" 검색 시 한국 특화 모델 **0개** → 온율티가 최초 진입.

---

### 3. 핵심 기술

#### 3.1 마커 단일패스 (Single-Pass Markers)

```
입력: [상태] + [질문] + {"route":□, "urgent":□}
                                              ↑ 마커 직전 로짓이
                                                해당 필드의 답을 예측
```

- JSON 스킬레톤을 프롬프트 끝에 붙임
- 마커(□) 직전 위치의 로짓이 각 필드의 정답 심볼 예측
- **N개 필드가 1회 forward로 동시 결정** (디코딩 루프 없음)
- 9B 모델 기준 지연: ~100-300ms

#### 3.2 제약 디코딩 (Constrained Decoding)

```
합법 심볼만 로짓 제한 → softmax → 모든 옵션에 확률
예: {"가스안전과": 0.87, "상하수도과": 0.05, "도로과": 0.08}  (합계=1)
```

#### 3.3 타입별 온도 보정

```python
# choice와 noul 각각 다른 온도로 보정
T_choice = 1.35  # 홀드아웃에서 Brier 최소화
T_noul = 1.20
```

- ECE 0.001 수준 달성 — "확률이 곧 신뢰도"

#### 3.4 int8 LoRA (핵심 발견)

| 양자 방식 | 격전지 정확도 | 발견 |
|-----------|--------------|------|
| 4비트 (nf4) | 0.788 | 확률 판단 정밀도 **붕괴** |
| **int8** | **0.818** | 4비트 대비 **+3pp** — 디시전 모델은 확률이 본체라 양자 손실에 치명적 |

### 4. 14세대 실험 전체 기록 (Ablation Story)

#### Phase 1: 기초 확립 (v0.1 ~ v0.3)

| 버전 | 접근 | 격전지 | 한국생활 | KMMLU | 핵심 발견 |
|------|------|--------|----------|-------|----------|
| v0.1 | 4B, 도메인만 | — | 96.3% | — | 일반지식 붕괴 발견 |
| v0.2 | + 일반 믹스 | — | — | — | 회복 |
| v0.3 | 4B 확정 | — | — | — | 베이스 상회 |

**발견 1**: "파인튜닝은 지식을 만들지 않는다 — 단, 보유 지식의 발현을 극적으로 최적화한다"

> 초기 KMMLU 점수(~30%)는 변환 버그로 잘못 측정됨 → 수정 후 v11(9B) = **45.4%**, 베이스 제로샷 23.4%에서 **+22pp** 향상. 이는 한국 특화 2.1B 모델(Kanana 44.8%)과 동급.

#### Phase 2: 한국 특화 심화 (v0.4 ~ v0.6)

| 버전 | 접근 | 격전지 | 한국생활 | KoBEST | DI |
|------|------|--------|----------|--------|-----|
| v0.4 | 한국생활 7도메인 | — | **99.7%** | 81.0% | — |
| v0.5 | Kanana-2.1B (한국 베이스) | — | 99.8% | 71.9% | 8.91 |
| **v0.6** | Qwen 4B 최적화 | **80.7%** | 99.8% | **84.3%** | **29.73** |

**발견 2**: 한국 특화 베이스(Kanana)는 국제 벤치에서 부적합 → 범용 베이스(Qwen)가 균형 최적

#### Phase 3: 미세 조정 (v0.7 ~ v0.9)

| 버전 | 접근 | 격전지 | 변화 | 발견 |
|------|------|--------|------|------|
| v0.7 | 소프트라벨 CE | 80.5% | -0.2 | 한국인덱스 +3.1pp ↑ |
| v0.8 | 격전지 5배 업샘플 | 80.4% | -0.3 | **플래토 도달** — 데이터 양만으론 한계 |
| **v0.9** | 버려진 10.75% 복구 + gold 소프트라벨 | **80.95%** | +0.25 | max_len 768이 **격전지 데이터 10.75%를 버리고 있었음** |

**발견 3**: 학습 시퀀스 상한(max_len)이 데이터 손실의 숨은 원인 — p90=774인데 컷이 768

#### Phase 4: 9B 스케일업 (v0.10 ~ v0.11)

| 버전 | 접근 | 격전지 | 발견 |
|------|------|--------|------|
| v0.10 | 9B 4비트 QLoRA | 78.8% | 4비트 양자가 확률 판단 **붕괴** |
| **v0.11** | **9B int8 LoRA r32** | **81.8%** 🏆 | **최종 챔피언** — 27B급 격파 |

**발견 4**: 같은 9B인데 4비트→int8만 바꿔도 +3pp — 디시전 모델의 양자 민감도는 NLP 태스크와 다름

#### Phase 5: 한계 탐색 (v0.12 ~ v0.14)

| 버전 | 접근 | 격전지 | 발견 |
|------|------|--------|------|
| v0.12 | 2단계 학습 (general→specialized) | 79.9% | 리더들이 쓰는 방식이 우리에겐 **역효과** |

| v0.14 | v11 이어학습 2에포크 | 80.2% | v11은 이미 **국소 최적점** |

**발견 5**: v11의 레시피가 이 하드웨어의 물리적 최적 — 추가 학습은 모두 하락

### 7. 규정 준거 판단 (신규 태스크)

대학 규정문(HWP)을 파싱하여:
- **주제 라우팅**: 조항이 다루는 사안은? (choice)
- **수치 요건 판단**: "학기당 18학점 초과 신청 → 위반?" (noul)
- **적용 대상**: "이 조항의 직접 대상인가?" (noul)

→ 79.1% 달성 — "규정을 주면 판단한다"는 닫힌 세계 문제로, 지식 한계와 무관

### 9. 한계 (정직한 평가)

1. **일반 지식**: KMMLU **45.4%** (v11 기준, 수정 후) — 파인튜닝으로 베이스(23.4%) 대비 +22pp. 단, 세계 지식의 절대량은 9B 베이스가 결정
2. **국제 종합 지수**: DI 30.7은 중위권 — 상위권(60+)은 27B급 또는 전용 아키텍처 필요
3. **격전지 0.8pp 차이**: 1위(0.826)와의 갭은 데이터 품질·양의 격차로, 단일 GPU 내 레시피로는 좁혀지지 않음
4. **옵션 한계**: choice 최대 26개, state 최대 6,000자

### 11. 교훈 (What We Learned)

1. **디시전 모델은 확률이 본체** — 양자 정밀도(int8 vs 4bit)가 3pp를 만든다
2. **숨은 데이터 손실을 찾아라** — max_len 컷이 격전지 데이터 10.75%를 버리고 있었다
3. **더 큰 베이스 ≠ 항상 좋다** — 27B(0.812) < 9B(0.818), 레시피가 크기를 이긴다
4. **소프트라벨은 태스크별로 다르게 작동** — 한국인덱스 +3.1pp, 격전지 -0.2pp
5. **부정 결과도 자산** — 14세대 중 10세대가 "실패"였지만, 그게 최적점을 찾은 이유
